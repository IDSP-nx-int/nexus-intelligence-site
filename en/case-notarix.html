NOTARIX — Notary Operations Platform with LFPIORPI Compliance

A Dataverse-centered platform that centralizes notary cases (trámites), enforces LFPIORPI rules, manages evidence, tracks municipal deadlines (semaphores), and automates document generation using tokenized Word templates.

1) Context / Problem

Notary operations were fragmented across spreadsheets and scattered files, increasing the risk of missing municipal deadlines, weakening evidence handling, and making LFPIORPI compliance dependent on manual calculations and individual interpretation.

2) Solution (what I delivered)

Core modules delivered

  • Case 360 (Trámite 360): centralized tracking (clients, amounts, payments, SAT folios/receipts).
  • LFPIORPI automation: threshold evaluation, flags, and policy-driven calculations.
  • Municipal semaphores: configurable deadlines (Red/Amber/Green) per municipality.
  • Digital case file: evidence centralized and linked to each case.
  • Document automation: Word templates using dynamic tokens for standardized outputs.

Delivery style

  • Deployed inside the client’s Microsoft tenant.
  • Model-first design: normalized tables + catalogs for scalable behavior.
  • Auditability as a first-class constraint: evidence, traceability, and controlled outputs.

NOTARIX reduces compliance risk and operational variance without increasing manual workload.

3) Architecture

Data

  • Dataverse-centered model with normalized entities + catalogs (parameter-driven rules).
  • Compliance logic supported by structured fields (thresholds, flags, timelines, evidence pointers).

Automation + Docs + Reporting

  • Power Automate: orchestration for traceability (notifications, logging, document outputs).
  • SharePoint/OneDrive: templates + evidence storage + links from Dataverse records.
  • Reporting: operational control views and export-ready outputs.

4) Key Features

  • Municipality-based semaphores with configurable deadline rules (per locality).
  • 6-month accumulation logic (grouping by RFC + act family; accumulated amounts vs threshold).
  • UMA versioning (parameter-driven values for calculations across periods).
  • SAT notice control (folios, substitutions/cancellations, and expiration tracking).
  • Draft → Officialization workflow (finalize only when evidence and required data are complete).
  • Token-based document automation using client-configurable Word templates.

5) Metrics / Scale (target)

Scale

  • Users / roles: 2 (Notary / Accounting)

  • Automations (flows): 2

Compliance targets

  • Deadline types tracked: municipal and federal

  • Primary risk reduced: manual calculation variance + missing evidence + missed deadlines
