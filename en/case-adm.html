1) Context / Problem

This build focuses on model-driven app design and Dataverse architecture in a realistic domain: procurement and inventory. The goal is an end-to-end process flow (RQ → OC → receiving/stock), with process enforcement through BPF and approvals.

2) Solution (what is implemented)

Core delivered

  • Model-driven navigation with modules: Almacén, Compras, Proyectos, Catálogos.
  • Dataverse schema with normalized core tables and explicit relationships.
  • BPF for Requisition (RQ): Capture → Approval request → Resolution → Close/fulfillment.
  • BPF for Purchase Order (OC): Capture → Approval request → Resolution → Receiving/Payment.
  • Approval automation via Power Automate (Approvals), updating record status.

Design focus

  • Dataverse table design: lookups, choices, ownership, consistent naming.
  • Process enforcement: BPF stages and controlled status transitions.
  • Automation wiring: approval requests and Dataverse updates.
  • Documentation artifacts: ERD, schema, BPFs, and automation screenshots.

3) Architecture

Data model

  • Dataverse-centered schema for procurement and inventory.
  • Core entities cover requisitions, purchase orders, inventory movements, and catalogs.
  • Relationships support automation and reporting without hardcoding.

4) Key Features

  • Process-driven UX: users follow the BPF stages.
  • Normalized schema: catalogs referenced by lookups.
  • Approval outcomes: flows update status fields to reflect decision.
  • Inventory trace: movements linked back to requisitions and purchase orders where applicable.
  • Documentation: ERD, schema, BPFs, and automation screenshots.
